# SL205 — Project settings disable SL/PYD codes

## Cause

A `per-file-ignores`, `extend-ignore`, or inline `# flake8:` block
disables one or more SL/PYD codes project-wide. This bypasses the
registry and removes per-construct review.

## Fix

Remove the disable from the config file. If the suppression is
intentional, document it in `[tool.supyrliminal.suppressions]`
and use `# noqa: SLxxx` per construct instead.

## Detection

SL205 is emitted by the `supyrliminal scan-config` CLI, not the
flake8 plugin. flake8 routes tree plugins through `ast.parse` first,
which raises `SyntaxError` on `.toml`/`.cfg`/`.ini` files; config
scanning therefore ships as its own subcommand:

```console
supyrliminal scan-config            # walk the current tree
supyrliminal scan-config /path/to/project
```

Output is flake8-compatible (`path:line:col: SL205 message`) so it
slots into existing tooling.

## Suppression

SL205 cannot be silenced by `# noqa`. Fix the config.
